# Security Policy

## Supported version

We have a simple process, and we do not have a formal release processing. We would gladly change
that if someone volunteers to manage it. For now, the best strategy is to update regularly.

## Reporting a Vulnerability

The best way to report a vulnerability is to open an issue. If there is a reason to keep the security
issue private, please send an email to the project manager.

Our small project is not able to support a full CVE process -- in particular, we cannot really manage
a separate "secret" code tree in which to prepare fixes and keep them secret until the release date.
If you submit an issue, we will prepare a fix in a normal PR, while keeping the documentation of that
PR to a minimum in order to avoid painting a big target for hackers.

Once the issue is fixed, we (or you) will enter an issue describing what was just fixed, so we have
a trace and your contribution is credited.
